# 正文生成规范

用于把提纲和场景事实转化为小说正文，也用于整章或局部修订。正文质量统一以 `skills/score.md` 的十项标准为准；本文只规定写作与修订流程，不重复定义评分标准。即使没有 `Data/`，本规范也必须能够独立执行。

## 工作顺序

完成 `AGENTS.md` 规定的事实源读取后：

1. 确认本章目标、阻力、人物选择、不可逆结果、固定钩子及相邻章节承接。
2. 按 `skills/score.md` 的十项标准主动设计正文，而不是写完后才拿它评分。尤其在动笔前确认关键因果、空间、视角、人物与对白约束。
3. 先写人物在明确空间中做事，让背景、制度、能力和情绪通过行动及后果进入正文；提纲和场景表规定事实，不直接提供正文句子。
4. 完稿后再按同一套 `skills/score.md` 标准复查；优先修硬逻辑、空间与视角，再修人物、对白和表达。
5. 篇幅由事件、关系和高潮完整落地后自然形成，不为凑字数扩写，也不为统一章长删掉必要因果。

## 人工偏好样本

`Data/` 中的 SFT/DPO 是作者对具体写法的人工正负样本，是对 `skills/score.md` 抽象标准的补充校准，不是当前章节的历史修改日志，也不是正文事实源。

- 没有相关样本时，直接按 `skills/score.md` 写作和修订，不得因为缺少 Data 停止工作。
- 只有当抽象标准不足以确定具体尺度、某类问题反复出现，或需要校准作者个人偏好时，才检索少量高相关样本。
- 检索按“当前写作问题”而不是章节号进行，可以跨章节使用对白、空间、视角、旁白、节奏等相似问题的样本。
- 同时查看选中稿、真实否决稿和作者理由；只迁移写作偏好，不移植其他场景的事实、人物关系或具体句子。
- 不全量载入 `Data/`。样本库可以持续增长，单次修订只把少量最相关样本加入当前上下文。

## 修订流程

整章修订时：

1. 先按 `skills/score.md` 评估最新正文，记录基线问题；历史评分不能代替现稿诊断。
2. 确定本轮三至五个最高收益问题；已经解决的内容不因重新评分而反复改写。
3. 必要时按上述规则检索人工偏好样本。
4. 逐处修改并连读衔接。关键画面只补会改变人物选择、空间状态或高潮结果的必要信息；复杂调度确实需要时才展开，不把作者脑中的完整空间模型搬进正文。
5. 用同一 `skills/score.md` 复评。自评分数不等于作者验收，新稿未经确认不得记为人工偏好。

局部修订时：

- 未明确要求改剧情时，保留既定事件、结果、视角、人物边界、章节钩子和场景事实。
- 直接定位目标问题，只作必要的替换、合并和删除；改后连读前后文，检查是否制造新的因果、空间、视角或人物问题。
- 若当前问题属于作者曾反复修正的类型，可检索少量跨章节 SFT/DPO 作校准；否则无需为了“使用 Data”而强行读取样本。

## 高频失败复查

以下三类问题即使总评分尚可，也必须单独复查：

1. **对白是否像活人。** 对照 `skills/score.md` 的“人物辨识度与对白”：检查是否又出现任务 UI 式一问一答、几个字几个字往外蹦、人人完整回答上一句、为了推进剧情而说话。短句本身不是问题；人物此刻为什么说、对谁说、真正关心什么，必须成立。
2. **场景是否一遍成图。** 对照“场景成图与空间连续”：入口、出口、遮挡、人物位置和关键物件应让读者第一次阅读就形成稳定画面。若一个机制必须不断补解释才能看懂，优先简化机制，而不是继续增加楼板、支撑、绕路、搬运等空间说明。
3. **是否出现解释性旁白。** 对照“动作与心理呈现”“贴身感官与运镜”等项：动作、对白或画面已经表达清楚的内容，不再由旁白复述意义、替人物总结动机、提前解释战术用途或事后证明设计合理。

## 本项目基调

- 末世压力不仅来自怪物，也来自资源如何分配、危险由谁承担、谁有权决定他人的价值。
- 残酷制度必须解决过真实问题，理想制度也必须支付资源、效率和牺牲的代价。
- 希望来自人物看清代价后仍选择共同承担，不来自突然出现且免除代价的救世力量。
