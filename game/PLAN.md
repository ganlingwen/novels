# 灰雾行者 · 单机 RPG 计划

## 文档职责与规格驱动开发

本文件是游戏产品要求、体验约束和验收标准的事实源，适用于增量开发、换引擎、2D 转 3D，以及从零重写。不能依赖对话历史或现有代码来恢复这些要求。

- **先规格，后实现，再验收**：开始工作先完整读取本文件，选定本次要满足的要求编号；规格缺项时先补充，再实现与验证。
- 当前用户明确要求优先；游戏体验与功能以本文件为准；小说世界事实按下文对应文件核对；现有代码只代表实现现状。
- 新需求和试玩反馈应更新对应规格与验收条件，不能只写进聊天或临时任务列表。尚未决定的事项标为待定，不冒充用户已确认。
- 重写时保留本文件及 `game/AGENTS.md`。目录结构、类名、绘制方式和既有界面都可以更换，已确认的产品要求不能随实现一起丢失。
- `README.md` 说明当前版本如何运行；“当前状态”记录已实现与未达标项；它们不能降低本文件的目标要求。
- 小改动直接维护本文件即可，不强制新增多层文档或逐次请求批准。当前用户已授权的开发可按明确规格继续。

## 用户体验要求：画面优先，交互直观

**必须保留的用户反馈：**“怎么全是文字？太不 intuitive 了。游戏不一般都是画面的吗？”

这说明首个原型虽能验证战斗规则，但没有满足游戏体验要求。后续开发和从零重写都不能继续以常驻说明文字、表单和系统面板作为主要体验。功能测试通过不等于体验验收通过。

| 编号 | 必须满足的规格 | 可观察的验收条件 |
| --- | --- | --- |
| VIS-01 | 战斗场景是默认界面的主体 | 正常游玩时，人物、敌人、道路和建筑构成主要画面；属性、天赋、背包、操作说明和日志不常驻占据整侧屏幕 |
| VIS-02 | 对象靠外观即可辨认 | 不看名称标签，也能区分玩家、丧尸、建筑、掉落物和基地入口；玩家与敌人不能仅用几何形状加名字充当最终表现 |
| VIS-03 | 动作和战斗状态可见 | 移动有步行动画，攻击有动作与命中反馈，受击与倒地有变化；技能有可区分的特效，Boss 危险区域在伤害生效前清楚显示 |
| VIS-04 | 主界面信息精简 | 保留生命、必要资源、技能栏、简短任务目标及导航提示；技能用图标和冷却遮罩表示状态，名称或解释按需出现 |
| UX-01 | 不读说明书也能开始 | 进入游戏即可看见自己的角色、可交互入口和明确的出发提示；第一次出发不依赖 README 或助手口头教授快捷键 |
| UX-02 | 交互发生在场景里 | 接近入口出现“出发 / 回城”提示；掉落有清晰标记与拾取反馈；升级时出现短暂提醒及加点入口，提示不遮挡持续战斗 |
| UX-03 | 成长界面按需打开 | 通过可见按钮打开属性、天赋和背包，再返回场景；默认战斗画面不要求同时阅读这些系统。快捷键只是补充入口 |
| UX-04 | 自动模式容易发现与理解 | 有可点击的模式切换控件和当前状态提示，无须先知道 Tab；能观察到自动移动、攻击与取核，手动移动可立即接管 |
| UX-05 | 反馈及时，文字辅助 | 命中、拾取、升级、任务完成通过动作、特效、图标或短提示反馈；不能仅把事件写进日志让玩家自行寻找 |

文字仍可用于剧情、物品属性和天赋解释。上述要求约束的是默认游玩体验，并不禁止必要文字。

**仍待确定的美术选择：**像素风或手绘风、具体人物造型、动画资源方案、固定或跟随镜头、是否使用小地图。可以先做统一风格的视觉样板；这些选择不能成为退回纯文字面板的理由。2D 简单不等于用调试界面代替游戏画面。

## 体验验收流程

每次涉及主界面、场景呈现或重写，必须在实际运行的窗口中完成以下检查，并注明对应规格是否满足：

1. **初见**：展示默认画面，不额外口头讲解；请首次试玩者指出自己、敌人、出口及出发入口。开发者自检只能算预检，不能冒充用户已经认可。
2. **出发**：从场景内提示开始行动，不先打开 README，不先阅读整页规则。
3. **战斗**：观察移动、普通攻击、技能、受击、敌人倒地和取核；检查这些事件能否从画面直接理解。
4. **自动与接管**：点击可见控件切换自动，观察寻路和战斗，再手动移动接管；检查当前控制状态是否明确。
5. **成长与返回**：从升级提示打开成长界面，完成一次加点或换装，关闭面板继续游戏，再完成回城。
6. **证据与结论**：保留默认画面、战斗画面和按需面板的截图或短录像；分别报告功能检查与体验检查，未验证项明确标为未验证。

自动化测试覆盖数值、状态与完整流程；截图检查覆盖布局和可辨识性；首次试玩反馈覆盖是否直观。不能用“测试全部通过”“截图文件已生成”或“程序成功启动”替代 VIS / UX 验收。

## 已确认方向

- 以本仓库小说世界为背景，先做俯视角 2D，后续考虑 3D。
- 单机、即时战斗；手动、辅助、自动三种操作模式，随时接管。
- 包含属性点、天赋、装备、技能、打怪升级。
- 使用 Godot 4.5，先交付 macOS 可运行原型。无服务器、联网账号或付费机制。

## 世界观与改编边界

小说事实依照 `../power.md`、`../factions.md`、`../characters.md` 和 `../outline.md`；游戏新增规则单独记录，不反向修改小说。

- 玩家是新幸存者，首个任务发生于猎鹰外围的一处废弃街区。
- 角色经验等级代表训练进度，区别于世界观中的一至三级异能能级。首版角色 1～10 级，仍处于一级能级，不实现突破。
- 晶核不能增加经验或直接提升异能能级。丧尸倒地不算死亡，玩家靠近完成取核后才结算经验。
- 技能积累短期负荷，武器作为低负荷战斗方式；晶核抑制机制、主动透支、永久崩坏留到后续，不在原型里冒充完整崩坏体系。
- 原型任务由玩家协助搜寻队清理街区；取核数量属于待上缴物资，不建立自由交易经济，也不允许私藏变现。
- 雷系技能、装备词条、角色等级和天赋效果是为游戏新增的设计。
- 现有机制原型使用程序绘制的角色与地图，仅用于验证规则。后续画面必须满足 VIS-01～04；可以使用程序绘制，但不能以此豁免可辨识造型、动画和打击反馈。

## 玩法与系统

基地整备 → 出发探索 → 战斗、取核和拾取 → 击败节点守卫 → 返回基地交付 → 领取奖励、调整流派、再出发。

| 系统 | 完整方向 | 第一阶段范围 |
| --- | --- | --- |
| 地图与任务 | 多基地、多区域、剧情和阵营 | 一个整备基地入口、一张障碍物街区、一次清理委托 |
| 属性 | 体魄、力量、敏捷、精神 | 每级 3 点；生命/体力、武器威力、攻速/闪避恢复、异能威力 |
| 天赋 | 公共树与异能树，有限点数 | 12 节点；连锁与聚能互斥；每级 1 点；基地洗点 |
| 装备 | 六槽、词条、制作、特殊效果 | 六槽、15 个装备模板、4 档品质、背包手动换装 |
| 技能 | 主动、被动、能力分支 | 雷击、连锁电弧、震雷、蓄能护盾；4 主动槽 |
| 敌人 | 丧尸、异化兽、敌对人类 | 游荡尸、疾行尸、硬肩尸、枝印精英、节点守卫 Boss |
| 操作 | 手动、辅助、自动 | 三模式；自动移动、攻击、技能、喝药、躲避预警、取核、返程 |
| 存档 | 多槽、版本迁移 | 单槽、原子替换、损坏备份；记录成长、装备、任务结算 |
| 战斗体验 | 音效、动画、打击反馈 | 现有原型已具备伤害数字、攻击轨迹与预警；下一交付优先满足 VIS / UX 规格 |

## 操作原则

- 手动与 AI 共享攻击、技能、资源消耗和碰撞判定。
- 辅助模式自动攻击和释放技能，玩家负责移动。自动模式额外接管移动。
- WASD / 方向键移动；移动输入暂时覆盖 AI，之后恢复自动。
- 鼠标左键攻击，1～4 技能，空格闪避，Q 药品，Tab 切换模式，E 基地交互，Esc 暂停。
- 战斗外调整装备和天赋；自动不消费晶核，不代替剧情决定。
- 新手死亡返回基地，保留成长，不掉装备；当前行动重置，不发委托奖励。
- 随时可暂停。关游戏保存成长，但中途退出后回到基地并重置本次行动，不存怪物和掉落现场。

## 2D → 3D

以下文件分工描述当前实现，可在重写时调整；需要保留的架构原则是成长与战斗规则独立于具体画面、输入和二维空间实现。

- `scripts/rules.gd` 管属性、经验、技能数值、装备和天赋；不依赖画面节点。
- `scripts/world.gd` 管二维位置、障碍、AI、碰撞与战斗调度。
- `scripts/main.gd` 管绘制、输入和界面；存档独立放 `scripts/save_store.gd`。
- 三维升级时复用规则与数据，重做世界空间、导航、命中、模型、摄像机和动画。不会承诺仅替换美术就能完成迁移。
- 原型技能命中采用二维距离；日后由三维世界提供命中目标，继续调用规则层。

## 分阶段交付

1. **机制闭环**：上述第一阶段系统；验证启动、成长、战斗、存档与自动完成任务。此阶段完成不代表产品体验达标。
2. **画面与直观交互，当前优先级最高**：先做默认场景、可辨识角色与敌人、动作及命中反馈、精简 HUD、场景内提示、按需成长面板与可见自动开关，按 VIS / UX 验收；再调整节奏、掉落、负荷与 AI。
3. **内容扩展**：多地图、多能力、阵营、制作、故事任务、正式崩坏与感染系统、能级突破。再评估 20～30 分钟内容是否足够。
4. **正式发布与 3D 决策**：打包、跨平台验证、存档兼容；先确认继续俯视角还是改第三人称，再制作三维样板。

第一阶段不做开放世界、多人、离线挂机收益、完整四基地剧情或第三人称战斗。

## 验收

- 游戏体验同时满足 VIS-01～04、UX-01～05，并完成实际画面与首次试玩验证；功能验收不能覆盖或豁免这些条件。
- 能在本机启动并完成出发、击杀/取核、Boss、回城交付与再次出发。
- 属性、天赋和装备确实影响结算；技能资源不足不生效，冷却不可绕过。
- 自动模式可完成整次行动，不需要玩家帮助绕过墙体；移动可随时接管。
- 暂停时生命、敌人和冷却停止变化。
- 保存后重新启动保留等级、点数、天赋、装备、背包、委托完成次数。
- 测试使用独立路径，不覆盖玩家存档。
