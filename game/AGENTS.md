# 游戏开发协作规范

- 开始修改、扩展或从零重写游戏前，完整读取本目录的 `PLAN.md`。它是游戏需求、体验约束和验收标准的事实源；不要仅根据现有代码重建需求。
- 特别遵守 `PLAN.md` 的 VIS / UX 规格：画面优先、对象可辨认、动作有反馈、成长面板按需打开、场景内交互、自动模式有可见入口。用户已否定文字占主导的调试界面，不能在重写时恢复该设计。
- 先明确本次对应的规格与验收条件，再实施；新反馈更新对应规格，避免只留在对话中。无需对已授权且规格明确的工作反复请求确认。
- 小说设定按照仓库根目录 `AGENTS.md` 指定的事实源核对；游戏新增规则记录在 `PLAN.md`，不要反向覆盖小说。
- 现有脚本划分、引擎和美术实现不高于产品要求。重写保留 `PLAN.md` 与本文件，并据规格重建实现。
- 分开报告功能验证和体验验证。自动化通过、成功启动或生成截图均不能证明画面直观；具体流程见 `PLAN.md`。
- `README.md` 保持当前可运行版本的真实说明；未实现、未验证的规格不得写成已完成。
